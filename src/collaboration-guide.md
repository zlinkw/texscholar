# TeXScholar 当前任务协作协议：一次提交排序后的三个方案

本协议只约束当前插件任务，不修改全局 SKILL、AGENTS 或真实论文配置。作者要求和科研证据优先。正式正文、已接收成果、手动修改及暂存选择受保护；未接收候选与批注是可替换工作内容。接收、Git 备份与科学问题解决是三件事。

## 日常修改的最短完整流程

1. 首次 read_context 核对插件版本和 file_roles。已有编号传 ids，新位置传 scopes 的精确 quote（插入点为空并给 left/right）或完整 section 命令；需要全文才传 files。默认返回全部未决项及相邻段落，不自动发送整篇源码。sources 是上下文，不是扩大改动的授权；global 作者规则、local 局部注释、reference 模板要求分开处理，模板不能覆盖作者规则。
2. 按任务选 modules；只在本会话确实仍有对应规则时传 known_rules。返修附件有 known_feedback 时原样传入：工具会重读当前源文件和状态，未变的原文、候选、批注可标 feedback_reused 而不重复返回，其他上下文照常提供。附件缺失、上下文丢失或版本失效时不得声称已经持有；新版返回优先，不要求恢复被废弃的旧批注。缺少必要依据时按需补读，不用工具成功冒充科学核验。
3. 直接组织 A/B/C 并保存。单项用 propose_options/rework_options，多项用 submit_options；apply 默认 true，无需预览后再写一遍。下一次写入使用成功回执的 sha256/version，不逐项重读、重算摘要或编译。成功后简报实际编号和目的即可。维护 CLI propose-options 不属于日常 MCP 的额外步骤。
4. 外置状态中的 rework_options 默认保留既有批注和候选历史；按作者明确要求才使用 discard_annotations 或 resolve_requests。旧内嵌状态的默认行为不同，需保留当前批注时明确传 discard_annotations=false；旧格式迁移前不能假称所有批注都能由新版界面管理。审核目录可多选后用“所选批注 → Codex”只交接选中项，加入输入区后仍由作者检查和发送。元数据关联绝不清除批注；返修不等于接收或解决科学问题。失败保留原状态，旧版本可按需读取。
   可选 `fulfillment` 逐条说明本版如何尝试处理批注：填写真实 request ID、request_version、request_text，以及方案、完整 after 内 Unicode 字符范围和精确 quote、explanation、status（attempted／partial／author／evidence）。未说明的要求仍开放；这些说明不是作者接收或科学验证。
5. question_refs 在读取结果中引用本次 context.questions；提交可在 question_pool 明确提供完整 {id,file,quote}，由各项 question_refs 引用。仅在本次请求内有效，不自动配对；每条摘录仍由工具核验。新候选直接带关联，只补关联用 link_questions，也可放入 submit_options。 submit_options 的 propose/rework 操作可在操作层或 spec 内给 questions/question_refs；两层同时提供时按 spec 在前、操作层在后合并，并按完整 id/file/quote 去重。预检和保存使用同一份归一化输入，未知引用或不精确摘录报错。回执 questions 是实际保存后的完整关联列表，可据此核对，不能把已保存操作重复提交。replace=true 才替换整组关联。
6. 批量首错停止，results 中成功项已保存，不能重放；只续写失败和未尝试项。invalid_field 的 field 指出需修正的位置，无需为修参数重读论文。状态、原文、版本冲突按 recovery 重读实际受影响范围，不盲目重试，不绕过写入锁或精确匹配。重叠错误的 existing 指向已有项，核对后返修，不自动合并。
7. references 可与 read_context 同时请求：每项给 kind（label/citation/macro）、准确 key 和 files。返回指定源文件中的真实定义及邻近内容；缺失或多处匹配明确报告。仅查定义可同时传 ids=[]。不执行宏展开，不把 BibTeX 条目当作已验证文献，跨段逻辑与科学事实仍由 AI 核对。
   作者明确要求保留的术语可作为 `protected_terms` 精确字符串随候选提交。审核页只提示数字、引用键、公式及这些术语的局部变化；提示不阻止接收，也不证明事实正确，未核对依据标记 unsupported。
   若有具体依据，先用 `read_context.evidence_scopes` 传项目内文件及 Unicode 字符 `start`/`end`，读取精确 `quote` 与 `source_revision`；返修或新候选的 `spec.fact_evidence` 将这些字段与方案 `option`、该方案变化的 `change_index`、`kind` 和 `change_old`/`change_new` 一并提交。后两项逐字复制 `read_context` 当前方案 `fact_changes` 中该变化的 `old`/`new` 数组；索引从零开始。可按这些结果用同文案重交并添加依据，旧内嵌状态需显式 `discard_annotations=false` 才保留批注。来源变动或候选更新后需重新读取并关联；界面只称定位已核对，科学结论仍未验证。缺依据保留 unsupported，不将引用存在当作科学证明。

## 返修批注与 SKILL 诊断

处理作者返修批注时，逐条结合实际批注、关联项与版本、原候选，以及三层来源：所有用户通用的实际适用 SKILL、本用户跨论文的已启用个人提示词、本论文背景。已有规则充分但未遵循时指出条款并纠偏；简略输入优先复用已知个人偏好和任务上下文，不猜造新偏好。明确要求“以后我的所有论文”才按当前资料身份与 revision 更新个人提示词；本论文事实、术语与约定只放当前论文背景，单处要求留在批注。范围含糊时询问仅本次、本论文还是所有本人论文。一般内容正常返修，证据不足标未知；不编造方法或实验结果。相同根因可合并处理，但须保留每条批注的对应关系。

每条意见的 purpose 为 revision（普通返修）、skill（完善通用 SKILL）、personal（完善我的跨论文习惯）、paper_requirements（完善本论文要求）、paper_background（补充或纠正论文背景）或 discussion（仅提问或讨论）；旧意见缺字段视为 revision。用途是意图线索，仍须理解作者原文；未选择用途的自然语言要求也同样处理。一条意见可同时包含局部返修、个人习惯和本论文约定，分别按实际授权处理；正文明确限定本段或本论文时不能扩大作用域。用途与文字冲突或范围含糊且影响长期保存时，只询问仅本次、本论文或所有本人论文。discussion 先回答，不自动修改候选或长期资料；skill 仍需先给出必要的具体方案并取得作者明确确认，选择用途本身不是批准。处理后简短说明实际返修及资料去向。

只有所有用户和论文可复用且实际适用的 SKILL 确有缺漏或含糊、确实必须修改时，先展示真实路径、原条款与拟改文字或差异、适用范围、原因、关联返修项，并说明为何个人提示词或论文背景不足，请作者选择确认方案后修改并返修、调整方案、仅按现规则返修或暂缓。只有作者明确确认具体方案后，才按 skill-creator 修改对应权威 SKILL，重新读取实际新文本并做必要验证，再按新规则返修相关未接受候选。未确认提案不是新规则；保存批注、交接附件及产品开发授权均不构成修改全局规则的授权。缺文件、权限、版本变化或需要重载时如实说明，不猜测生效，只暂停依赖该规则的返修。普通明确个人偏好可按作者授权更新个人提示词，不需改 SKILL；不自动接收或宣称科学闭合，不把论文或秘密复制到全局规则。

三层各自只记增量：公共方法继承 SKILL，不复制全文；个人提示词只记用户跨论文差异；论文背景只记本稿特例及来源，不复制个人提示词或审核状态。已有条目按明确意图修订，不能用模糊匹配静默删改。当前任务可覆盖个人默认，论文特例只在本论文适用；事实与安全底线不能放宽。背景与最新论文冲突时明确显示、核对来源，不能静默选旧内容。上述资料均不是发送、接收、运行命令或修改规则的授权。

## 候选生成

位置标题 `location` 默认使用简短中文，仅保留必要符号、编号及专有名词英文；旧英文标题可以提供 `location_zh`，无需改正文或重做候选。定位冲突项仍可读取；旧格式可用 `relocate_options` 核对精确位置，固定块模式须预览并经作者确认后用 `reassociate_block` 修复缺失标记或关联唯一移动的块。保留 ID、版本、批注与决定，不按全文相似文字猜测。作者明确要求拒绝未接收项时可用 `reject_options`；不自动接收或关闭科学问题。

- 文件角色须 confirmed，变化时让作者确认。正文、回复、模板按实际登记处理，不猜文件名或改模板。初始化新稿只在作者授权的写作任务内进行；安装工具不初始化论文。
- 每个原文位置提交完整、实质不同且排序后的 A/B/C；不凑同义版本。确实不足三个合理选项时写 fewer_options_reason。普通单元最多一个自然段；公式、图注、表注单独处理。最小充分修改，不为一句重写整段；新写或实质重写内容一句一行。
- 三方案共享真实事实、数值和限定条件，不编造实验、引文或因果。intent.goal/preserve 简述本次目的与保留内容，不新增计划审批；作者明确要求先确认时除外。reason 默认一句实际取舍，只有较长依据才另填 summary；after 始终完整。
- 手改候选的 manually_edited 说明原理由和排名可能过时；返修使用实际保存内容重新排序，不照搬内部标记。新版候选保留旧未处理和暂留批注的独立身份；不得自动接收、覆盖已接收成果或手动正文。
- 本论文作者约定及局部适用范围保存在论文资料中；背景事实与作者明确约束分开，不把背景当作操作授权。旧源码中的规则在明确迁移前仍需读取。新格式的审核状态由插件保存在 `.codex-review/state.json` 和对象目录；旧格式继续读取已有 CODEX-REVIEW-STATE。不能双写，也不另建跟踪文档。详细格式请求 writing，问题关联请求 questions；角色结构、界面和备份分别请求 roles、interface、backup。
- 只处理当前目标及必要依赖。跨章节判断补读相关内容；无证据结论标待核验。缺少当前插件版本信息或版本不匹配时重启实际 MCP 宿主，不改用另一个版本 CLI。

## 文件角色细节

每次论文任务先读 read_context 返回的 file_roles。插件按实际 TeX 内容、documentclass、input/include/subfile/import 和 !TeX root 提供建议，不要求特定文件名。只有 status=confirmed 才能据此写候选；unconfirmed 或 changed 时请作者在 VS Code 执行“TeXScholar：识别／确认论文文件角色”。不要自行伪造确认、猜测用途或绕过 MCP 检查。首次新项目可在作者授权下先创建必要模板骨架，但不能将草稿直接冒充已接收正文。

文件角色由插件本地论文资料保存，包含登记拥有文件和 files，structure 保存结构快照；file/root 均为项目相对路径，root=null 表示未指定编译入口。manuscript 是论文主文档，chapter 是正文子文件，response 是回复信，review 是原始审稿意见，template 是仅供参考的模板，other 是其他 TeX；一个文件可同时为 response 和 review。AI 仅在作者明确要求后以 read_file_roles 读取当前版本和结构，再用 write_file_roles 保存作者确认的完整角色；未经确认不猜角色、不搬迁 owner。旧源码角色块在明确迁移前仍按原契约读取，不会自动清除；与新登记冲突时停止核对。角色登记不初始化审核、不改变编号或审核决定。

增删改名、documentclass、包含关系或 !TeX root 改变才需重新确认；普通正文润色、保存、接收和批注不重做首次确认。动态宏和共享子文件可能无法唯一解析，按作者实际指定入口，不做模糊自动配对。template 不作为论文改写目标；确实需改模板，先请作者在文件角色中调整用途。confirmed 映射也是插件选择审核 PDF 主文档的依据。


## 界面与交付细节

插件更新与 MCP 进程更新分别核验。正式版更新由插件每小时检查或用户手动触发，下载、发布摘要和 VSIX 身份校验、安装均由插件按钮完成，不需要 AI 更新提示词。遇到 plugin_version_mismatch，以该会话实际返回为准；IDE 上下文不能证明连接属于 VS Code。根据连接拥有客户端重启：桌面端连接需要重启桌面应用的 MCP 或正常退出重开桌面应用，仅重启 VS Code 无效。保留原任务，使用插件的“保存文件，准备完整重启”（随后由用户正常退出重开）或“保存文件并重载 VS Code”后核对活动服务版本，再以当前实际安装版本调用 read_context 核对 plugin_version。请先等待当前 AI 操作结束并保留未发送输入；旧版服务无报告时属于待核验。插件不能替其他独立 Codex 客户端重启服务，其他客户端仍需在自身 MCP 设置中重启或正常重启客户端。不混用旧服务和新版 CLI，也不重放已成功的操作。

VS Code 内的 Codex 可通过“保存文件并重载 VS Code（刷新 MCP）”调用公开的文件保存接口和窗口重载命令；作者先保留未发送的聊天输入，保存失败或仍有未保存文件时停止。稳定启动器的 -X、utf8 与脚本路径通常不需要随版本调整，实际实现由 connection.json 指向。重载后继续核验 MCP 返回版本，不能直接宣布已更新。其他独立 Codex 客户端使用自身的重启入口。

按章节读取时使用实际完整 TeX 标题命令，不从模块名推测标题。section_selector_invalid 会返回当前 available_sections，可据此修正 scopes；相同标题需结合真实 left/right 区分，不自动选择近似标题。source_changed 的写入冲突仍需重读受影响源码。interrupted_transaction 需先只读检查 status，再用当前摘要显式 recover，成功后重读受影响编号并继续未保存操作；不能重放已成功项或删除事务记录。

作者可直接编辑正式 .tex，无需先生成候选。顺序完成的手动修改成为后续读取、生成、接收及备份的真实底稿；AI 下一次操作先使用当前源文件，不能恢复旧正文。干净源码模式接收时只精确替换作者选择的片段，其余手动修改保留在正文与工作投影；未接收方案和批注仍在独立审核对象中，不转为已接收。旧式候选仍写在正文中的文件继续用独立投影排除未接收内容，投影无法唯一对应则停止。当前候选原文被改动、版本失效或读写期间并发变化时仍停止，不模糊匹配。AI 不手改 DATA、对象历史或决定，也不因作者允许手动编辑就绕过候选审核直接重写正式正文。

作者可以保存草稿并切换审核项，也可在准备 Codex 交接时继续编辑；这些操作均不代表接收。批注附件只反映生成时的内容，AI 仍按核心流程核对当前状态与附件回执，不要求作者先处理可替换的旧批注。

read_context 的 question_refs 指向本次 context.questions 中的完整原始意见，相同 id/file/quote 只返回一份。写入可传完整 questions，也可显式构造本次 question_pool 并引用，由工具展开并精确核验，不按编号猜配。重叠错误返回 existing 的真实编号、版本和文件；按 recovery.ids 补读该项，再判断是否返修，不自动合并或接收。

问题关联必须提供实际 id、项目内 file 和唯一精确 quote。多个问题涉及同一原文位置时合并为同一修改项，在 questions 中分别关联，不自动猜配。完整接口见同目录 question-linking-guide.md。返修上下文包含编号、选项、版本、原文、候选与选区；批注只加入 Codex 输入区，不自动发送或调用 AI。

批注带 display_context 时，作者实际划选的是其中 quote，kind 区分审稿问题与中文译文，source_side/source 指明对应的英文来源，question 保留问题关联，text 是当时的完整阅读快照。结合这些信息理解作者要求，再修改对应候选。外围 side/start/end/quote 只负责把批注归属到原文或候选，不能把中文字符偏移套到英文源码上，也不能根据译文臆造新的审稿问题或修改原始审稿意见。保存、编辑和交接批注均保留此上下文。

作者可在批注编辑区使用“保存并加入 Codex”，仅交接本项待处理批注；顶部入口仍交接全部待处理批注。不要把交接快照当作当前状态，先核对最新版本再返修。作者手动编辑后的“保存并接收”是明确的作者操作，先保存所选方案再核对版本接收；AI 不拥有此操作，也不能因为普通保存而自行接收。

保存成功但交接失败时，作者可“重试本项交接”，只重试同一项的当前版本，不新增批注或自动发送。AI 收到重复交接时也先读当前状态，不重复创建候选或批注，不把重试理解为新的一轮作者要求。

审核页的公式预览／源码切换只负责显示。请提交真实 LaTeX，不生成预览 HTML，不为兼容预览擅删 label、改写公式或替换期刊宏。预览符号选区按整式绑定；细部批注使用准确源码范围，均保留现有版本核验。自定义宏与最终公式编号、排版以实际 PDF 为准。

候选 PDF 由插件处理：一份完整论文，仅修改句上下对照，未改内容一次；A/B/C 只决定显示哪个待审方案，不自动接收。不要向正式源码加审核颜色宏，也不要为普通 AI 改稿自行编译。插件允许用户配置保存当前预览方案／选择方案后的 PDF 更新，以及接收后的自动更新。

科研约定与适用范围保存在论文资料中，旧源码规则在明确迁移前继续读取；段落计划按实际局部范围保存或随任务说明，不自动向源码插入旧规则。新格式的交接和运行状态由插件维护在唯一 sidecar 及对象目录；旧格式继续使用已有 CODEX-REVIEW-STATE。固定块注释只保存身份，不能混入候选或批注。旧项目迁移须先预览并由作者明确确认，安装和普通更新不会触发迁移。

插件启动、正常保存及每五分钟检查已保存的论文源码，在后台备份手动修改和已接收内容；前台不等待 Git 或网络。范围外暂存选择保留，未决候选和批注不上传；自动备份不精简历史或缓存。状态区区分排队、本地提交、远端成功与失败，失败后可核对并重试；无归属本地提交或远端分歧不会被连带推送，也不阻止审阅或 PDF。

自动备份远端确认后，只有该次源码中核实包含的已接收版本可作为新批次的备份证据；后来接收的版本仍需自己的备份。作者明确选择“Git 备份已接收修改”时，原有收尾入口仍可备份及整理已完结记录，并按既有授权和引用核验处理无引用对象；普通自动备份不执行这些整理。不自动更改远端、强推、接收其他候选或宣称科学问题解决。

插件不能向任意 AI 聊天静默注入规则，也不能保证 AI 语义上遵守。常规入口是 VSIX 内置 MCP（read_context、propose_options、rework_options、read_feedback、link_questions）及同一审核核心的保存校验；也可从插件附带协议的写作上下文／返修交接继续。MCP 不提供作者接收或自动提交推送接口。上下文丢失后重新读取本协议与真实状态；修改全局 SKILL 须作者对具体方案明确确认。

审核编译缓存由插件在专属缓存锁内按文档自动轮换，不作历史备份；成功发布后保留各文档当前引用的编译目录，失败诊断保留到该文档下次尝试。AI 不自行删除活动编译缓存或复制旧快照供长期保留。该生命周期与成果推送后清理无引用审核对象分别执行，不改变待审候选、批注或作者决定。

服务已新于任务附件时，task_version_outdated 表示需要从当前插件重新准备任务／批注包并核实已安装版本，不是要求再次重启。保持版本拦截，不仅按服务自报版本降低 expected_plugin_version；优先使用作者新加入的插件包，不重复保存之前成功的项。

多个 MCP 连接本身不表示版本过期。各进程报告均匹配时正常使用；连接尚未处理首个请求而缺少报告时属于待核验，不要求仅因此重启。实际会话的版本不一致错误仍须处理，不能当作单纯多连接提示忽略。
