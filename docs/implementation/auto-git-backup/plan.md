# 保存与定时自动 Git 备份

## 目标与已确认决定

2026-11-21 用户批准继续多会话实现、验证、发布并安装。保存、插件启动及启用期间每 5 分钟自动检查并提交备份，无额外确认或提交说明弹窗。Git 只记录已保存的论文成果，包括手改及已接收修改；候选定位冲突不能阻断源码备份。自动生成有实际变更内容、时间和文件信息的提交说明，方便日后 AI 检索，不调用 AI 生成说明。

沿用现有仓库 master → origin/master、私有远端核验和后台串行 Git 队列。不新增备份分支、worktree、通用缓存或索引管理系统。优先 Git 原生按指定路径提交；范围内文件以当前已保存版本为准，可以取代其旧部分暂存选择。范围外暂存条目、对象和选择必须保留且不夹带。正常已有暂存不再成为自动备份的阻断条件。新需求取代旧 accepted-only 自动备份契约；旧手动入口保留，不混用“备份成功”和“审核完成”。

实际起点：0.9.51；master 与刚 fetch 的 origin/master 均为 4e3887cc6e32b24d74013601131372a442abbe91，工作区干净。旧自动备份依赖 source_review.py 接收投影；手改会触发 auto_backup_projection_error。auto_backup.py 还拒绝非空真实暂存区。需补齐实际调用链，不能只加计时器。

## 范围、保护与行为

1. 复用现有备份路径筛选、已确认文件角色和项目发现；明确自动范围，不能用 git add -A 或把任意新发现文件默认全上传。保护凭据、编译缓存、审核对象和范围外文件。已支持的论文资源/角色入口继续可用；新配置不默默改远端或创建仓库。没有审核批次、尚在普通写作阶段时，已配置合法论文项目也应能备份，不以有效候选/活动审核状态为前提。
2. 按已保存磁盘内容备份，不强制保存脏缓冲，不回写作者源码。相同内容不重复提交/推送；同一项目仅一个备份任务，启动/保存/5 分钟事件合并，执行期间再次保存排入下一轮。定时器仅随插件激活存在，dispose 后释放；不新增驻留服务。接收自己的正常保存走同一入口，移除或协调旧触发，避免两条自动备份管线并发。
3. 脱离候选定位、accepted projection 和审核状态协调；无关定位冲突或损坏审核元数据不应阻断可独立读取的正式源码备份。既有旧格式源码脱敏/运行数据不上传契约保留，不能直接把嵌入 DATA/未决候选的整份源提交出去；优先复用既有纯源码生成能力且不回写现场，不引入额外索引系统。遇到无法安全导出的真实旧格式失败要明确指出文件/原因，不自动迁移或猜测。
4. Git 原生精确路径操作优先。范围外暂存内容须在提交后语义不变；范围内提交内容须确实是捕获的已保存版本。Git hook、外部 Git、读取/提交期间新保存等实际并发不允许偷偷改变提交范围、夹带数据或覆盖源。沿用原 hooks 和支持的 EOL/BOM 行为，不通过 --no-verify 绕过 hooks。不能 reset/stash/rebase/merge/force 或擅自处理其他 Git 事务。
5. durable 备份记录只记备份事实，不写作者决定、候选版本/批注状态。旧已生成但未推送的任务不能丢失；启动时读取并核对实际本地/远端，能安全续传则续传，不连带上传无法归属的其他本地提交。不因旧投影错误阻断新已保存源码，不清空旧任务来伪装恢复。复用私有仓库校验、普通快进推送、远端结果核对；凭据/远端分歧真实失败明确可见，后续保存/定时/重开可重新尝试，不无限立即重试。
6. 状态区/现有输出中显示“无变化 / 排队 / 本地已提交，远端待上传 / 已备份 / 失败原因”，正常自动流程不弹窗、不抢焦点。旧任务完成只确认自己的版本，有后续保存时不能把最新状态标已备份。源码接收、自动协调、PDF 不等待 Git hook/网络，也不能被备份失败回滚。
7. 提交标题简洁表明自动论文备份及实际文件/类型；正文自动记录带时区的时间、触发来源、文件清单、增删统计及可可靠提取的章节/题号等定位信息。内容依据真实 diff，不能编造修改目的/科学结论，不包含私有候选或批注全文；Git diff 保留完整可检索源码变化。无必要信息不新增字段/摘要系统。

真实论文 D:/Overleaf/TMI-DA-Marked-up Copy 和其他真实项目只读。本轮不在真实论文触发 Git、接受/撤销、迁移、加标记、清空/精简审核状态或改正文；不直接编辑已安装扩展源码。审核状态、批注、决定、延期项、候选 ID/版本和草稿均受保护。安装完成也不擅自重载正在使用真实论文的 VS Code/MCP。

本轮不授权文件/目录清理。测试夹具与日志放 D:/latex-writing-checks/auto-git-backup-20261121，默认保留。已有旧目录的删除回归例外不扩大。未变清理代码无需为本轮另跑会删除夹具的全组；如受影响且必要，先报告精确缺口，按既有规则申请专项例外，不删断言/改超时/伪造通过。单人 20–30 项及单项接收小于 5 秒的既有需求保留，不增加压测或新性能阈值。
