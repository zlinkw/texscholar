## 核心设计

### 1. 独立的权威状态，不是可丢弃缓存

采用项目内单个 .codex-review/state.json 作为 schema 3 的权威运行状态，复用已有 objects、写锁、原子替换和事务恢复。以标准库及现有依赖实现，不引入数据库、服务、轮询守护或通用持久化框架。候选正文/基线继续放不可变对象，状态只引用它们，避免重复嵌入大文本。

state.json 保存批次身份、稳定 ID/计数器、不可变版本引用、方案选择与作者决定、批注/依赖、文档版本与位置绑定，以及必要的工程发现信息。文件角色等机器登记逐步由此读取，旧已确认角色可迁移；作者写作规则、科学内容、人工注释和段落计划不得当运行垃圾清理。新项目的发现、创建及恢复不要求先在某个 .tex 插入状态注释。旧 state 参数/命令入口保留，由同一个后端识别并路由，不能另建独立决定系统。

明确区分“状态文件”和“作者源文件”，不以伪造 embedded() 或把 JSON 当 .tex 源码维持旧接口。状态 CAS 与文档内容版本分别验证：作者改一段正文不能令其他候选批注写入丢失，元数据变化也不能让正式 PDF 报源码变动。状态文件缺失/损坏或双份状态不一致时明确报错，不默默初始化空批次。项目完整备份/恢复包括 state.json 及必要对象；源码 Git 与投稿导出排除运行状态及批注。

### 2. 以文档版本和范围为主的位置模型

新候选绑定 file、source_revision、start/end 和明确的插入亲和方向；位置与不可变候选版本分离。来源版本对应已有对象中的准确源码快照，摘要只用于版本核验。统一沿用现有 Unicode code-point/VS Code UTF-16 转换，保留 CRLF/BOM。

VS Code 内的作者编辑，利用真实 contentChanges 在内存中顺序变换未决范围，校验变换前后的完整源版本；保存时合并持久化，不每次按键启动 Python。插件自己接收产生的保存事件按源版本识别，不能二次位移。多项接收仍基于同一源版本预检和事务提交，更新所有受影响未决范围，一次刷新/后台任务调度。

插件关闭期间或外部编辑后的源码变动，比较已保存基线与当前文本，只在位置映射可唯一验证时变换范围。重复片段、移段、剪切粘贴、未知合并等存在多种对应关系时保留为冲突；不能仅因 diff 算法选出一种对齐就当唯一，也不能取第一命中、模糊近似替换或自动回退到其他候选。文本上下文仅供旧数据首次导入和作者明确修复位置，不再是 schema 3 日常接收的主定位条件。

保留现有 before/left/right 输入兼容入口，但新 MCP 与界面优先使用当前 read_context 返回的文档 revision 与准确范围。旧文字定位成功后转换为版本范围；不可定位则保留该项并提示修复，不猜测。需为 AI 提供可实际使用的当前版本/范围回执，不能仅添加字段而旧调用方仍反复猜锚点。

### 3. 作者手改是正式来源

范围外的手改正常保留并更新位置；范围内的手改同时保留当前源码、AI 备选、原决定及所有批注，标注“作者已修改，需核对”。不自动把手改视为接受、拒绝或科研问题闭合，即使刚好等于某个备选也只作核对提示。

旧候选仍能查看、延期、精确重新选位置和安全拒绝。需要以手改后的正文继续 AI 返修时，提供明确的“以当前源码为基准”操作/协议；在同一稳定 ID 下生成新不可变版本，旧原文和原候选留在其原版本，旧批注保留来源关系或明确标陈旧，不能自动移到相似文字。保存批注、同步范围和直接保存源码均不启动 AI。

接受只应用点击时明确的 ID/version/option，要求其注册源版本和范围内实际文本仍满足该候选的前置条件；有冲突就停止该次决定，不覆盖手改。部分批次接收、20–30 项典型规模、长期延期批注、多选各自 A/B/C 均继续支持，重启不重开批次。

### 4. 迁移与恢复

提供可审阅的旧 schema 1/2 → 3 迁移预览与显式应用入口，使用现有锁及精确期望版本。迁移保留 session、全部 ID/计数器、每个不可变版本、决定、问题关联、批注/依赖、accepted 投影及后台备份检查点。真正失效的位置原样保留为冲突，不因迁移伪造恢复。

正常打开旧项目继续可读且可使用既有路径，不自动删除或替换其状态；新项目使用 schema 3。迁移后只有一个活跃写入源，旧入口路由新状态，不做实时双写。迁移必须处理保存中断及作者并发手改，能核对恢复或停止，不能覆盖新文本。若保留旧头作为拒绝旧扩展写入的只读迁移标记，新后端不能依赖该注释来发现状态；是否保留及具体格式由实现以最小可用方式落实，必须在迁移预览中明示。
