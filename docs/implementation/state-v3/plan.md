## 设计

### 1. 一个外置权威状态

使用 .codex-review/state.json 作为 schema 3 权威状态，复用不可变 objects、共享写锁、原子替换和事务恢复，不新增数据库、服务或持久化框架。保存批次、稳定候选 ID/计数器、不可变候选版本、作者决定、批注、显式依赖、块登记及上次核对快照。块 ID 与候选 ID 分开；章节名、题号和标签是结构属性，不是候选身份。

区分状态文件、状态旧 owner 和作者源文件，不把 JSON 假装成 .tex。状态 CAS 与源内容版本分别验证；源变化不能覆盖其他候选状态，元数据变化不能令正式 PDF 报源码变更。状态缺失、损坏和双份活跃状态不一致应明确区分，不默默初始化空批次。作者规则、普通注释及科学内容保留，不能当插件垃圾清理。

状态发现不依赖 tex 注释；启用固定块模式时由插件在预览确认的必要边界建立标记。保留旧参数/命令入口并路由同一后端。工程备份包含状态及必要对象；源码 Git 可以保留仅含块 ID 的轻量标记以支持跨机，但排除候选、批注和决定等运行历史。投稿清洁导出只在副本去除插件标记，不改工作稿；不能为了保留标记而上传 sidecar。建立标记不算接收、不关闭问题，也不触发虚假的接收成果检查点。

### 2. 固定块 ID 为主，章节与题号为属性

在有候选/批注的最小单元及必要父容器边界添加成对 LaTeX 注释；未涉及的正文不强制逐段加标。示意 ID 已缩短，正式实现使用标准随机 UUID 并检查重复，不由正文摘要、行号、题号或候选计数器派生：

```tex
% TS-BLOCK-BEGIN id=b7a91 kind=paragraph
这里是当前原文，可以通过该块的审核卡片修改。
% TS-BLOCK-END id=b7a91
```

tex 内只放固定身份与类型，不嵌入候选、批注或大 JSON。标题名、章节号、审稿人/问题身份、父子关系及版本登记放在 sidecar。章节或题号变化不改块 ID；从最新结构读取显示名称，语义关联改变则提示核对，不能按顺序串号。块内原文即使整段重写仍能按 ID 找到；这只保证块身份，不保证旧建议或词句批注仍适用。

| 文档 | 父容器 | 最小审核块 |
| --- | --- | --- |
| 手稿/初稿 | 文件、章/节/小节、摘要、附录 | 自然段、公式、图表及图注 |
| 回复信 | 文件、审稿人、已核实问题身份，如 R2-Q3 | 回复段落、引述、公式及变量解释等 |
| 连续插入 | 明确的父容器与持久插入槽 | 每项候选有独立身份及次序，不只依靠相邻文本 |

审稿问题块可含独立子块，容器本身有批注才整体保护，不能因为某题有一个批注就锁整题。候选仍至多一个自然段，公式/图注独立。input/include 保留真实文件及包含路径；块完整移动且 ID 唯一可重新定位，复制导致重复 ID 则明确冲突。块内新增/拆分段落、删空块、合并块时，标明原有建议的适用变化，不悄悄创建新身份接管旧批注。通过插件新建审核块才分配新 ID。

标记仅插在语法安全的独立行边界，不插入命令参数、数学或 verbatim 内部；使用现有词法和平衡解析验证成对/嵌套、唯一性及范围。必须验证不改变 TeX 段落和空格语义、编号及 PDF 内容，不能仅因注释不打印就宣称排版不变。保留 CRLF/BOM、Unicode 与 VS Code UTF-16 转换。

所有读取/展示/接收/预览入口核对实际最新源码；源码与有效读取版本一致时复用已有块索引，实际变化才重建相关文件的标记索引，与 sidecar 登记对照。不通过全文 quote/left/right 搜索代替失踪 ID。标记缺失、重复、错配或跨文件移动证据不足时保留卡片并暂停对应项，显示文件、块/候选 ID 及具体原因；不能自动补一个新 ID 冒充原块。提供可审阅的“修复块标记/重新关联”操作，确认后才恢复。

### 3. 只保护活动审核块，通过卡片修改

推荐保护规则：

- 有待审候选或未处理作者批注的最小块受保护；候选全部处理且没有未处理批注后自动解除正文保护，固定 ID 保留供后续定位。
- 长期延期项只保护所在最小块，不锁整节/整篇；作者仍可从卡片编辑该块。周围未审核内容可直接手改。
- 卡片提供明确区分的“编辑候选”和“编辑当前原文”。编辑候选仅产生新不可变候选版本；编辑原文需作者点击“保存原文”，按当前块版本写入正式稿并记录作者手改，不记作接收某个 AI 方案。默认编辑候选，避免误写正文。
- AI 只有作者主动请求时才返修，走同一 block_id/版本校验接口；它提交候选而非自动接收，不能修改标记或绕过受保护块直接写正式稿。

保护强度必须诚实：TeXScholar 自己的卡片、MCP 和写入接口可以在提交前强制校验标记及写权限；普通原生 VS Code 文本编辑没有可对所有工具生效的分段文件锁。源码视图显示受保护提示和跳转卡片，外部编辑器、另一插件或直接写文件的 AI 仍可能绕过；检测到绕过后保留其最新正文，暂停接收并要求同步，不能自动还原整文件、偷改回原文或把数据丢掉。若要求源码中每个按键都绝对不能改保护区，需要额外受控编辑器并限制所有写入者，不作为本轮默认方案。不能把事后撤销扩展的效果称为操作系统级锁。

公开依据：VS Code 官方文档说明 TextDocument 仍可被原生编辑器、其他扩展和 undo/revert 改动；read-only-region 扩展采用改后恢复绕过普通编辑器缺少只读片段的问题。此次只借鉴保护提示与范围校验，不照搬整文件回滚机制。

### 4. 自动读取、状态更新与接收前提

无变化是正常主路径：用户直接点击接收或多选接收，完成必要的最新源核对和 ID/version 校验后提交；不弹“同步状态”、确认、修复位置或重新选择提示，不运行差异协调、批注迁移、候选重建，也不为一次无变化读取持久化新状态或生成候选版本。只有本次操作实际改变的决定/源内容需要提交。

比较对象为当前相关文件实际内容与上次成功核对的准确内容版本，以及最新状态中的候选身份、状态和显式依赖；不能仅凭 mtime、编辑事件未触发或旧缓存认定无变化。文件未变时复用现有块索引和批注映射；源变化时更新该文件索引，再按块判定影响，未变块及未变依赖直接通过，不把无关段落手改或批注元数据更新当作全项目失效。已有失效标记不能因本次未再变化而清除。

插件自身一次接收已在同一事务内更新源、块位置与状态，后续保存/刷新事件只核对并复用该结果，不重新当成手改要求用户同步。多选共用本次一致的源读取与预检，一次状态事务，避免逐项重复启动后端和刷新；最终写锁内的源/状态并发校验不可因加速而省略。已有后台调度合并保存、刷新及编译信号，不新增常驻监控或全项目指纹系统。

打开、read_context、刷新、保存及每次接收都核对最新相关文件。未受保护块的手改不阻断其他块；在块前插字/换行只改变导出位置，固定 ID 仍生效。编辑事件用于及时失效和合并刷新，不把完整编辑日志当恢复前提。未保存文档显示明确状态，暂停该文档接收，不偷偷保存；同项目活动 UI/MCP 共享写入阻断，未连接编辑器的独立读取明确只针对磁盘，不声称检测未知缓冲区。桥接优先复用现有通信，若不足先报告具体接口缺口，不另造通用服务。

受控原文修改或绕过保护的手改触发按块协调，无 AI 调用：

| 变化 | 更新及批注处理 |
| --- | --- |
| 块内容未变，仅位置/标题编号变化 | 自动更新位置和结构属性；候选、批注及决定不变 |
| 块内容有变 | 保留当前正文，暂停受影响候选接收，显示“正文已修改，需同步批注”；不能只改摘要恢复接收 |
| 手改与某候选差异严格不重叠，映射唯一 | 作者点击同步后确定性重放差异，生成最新原文上的新候选版本，完整保留手改；不改正式稿、不自动接收 |
| 差异重叠、目标删除/拆合、具体选段不唯一 | 旧建议/选段保持历史可见，标为过期，支持卡片内人工调整、拒绝或延期，不模糊替换、不取首匹配 |
| 标记损坏/重复 | 暂停该块；范围不明才扩大到该文件，显式修复前不继续写入 |

块级批注始终可挂在同一块；词句级批注只有准确选择文字与映射均未变且唯一才调整位置，原选段已变则显示“原批注，内容已变”，不猜其新含义。同步不得重置作者决定或把手改等于建议视作接受。某个 A/B/C 不能协调时不得偷偷删除该方案后报全部同步成功。

点击绑定 batch/item_id/block_id/version/option 及当前源版本，后端在共享锁下重读核验；过期停止，绝不回退至光标、活动卡片或另一项。多选含过期项时整次停止并列出名单，作者可取消这些项后再提交，不暗中接收子集。同步后的新版本必须先展示，再重新选择。接收成功统一更新插入槽/相邻位置和同文件登记，不丢其他候选/批注；长期延期、部分批次接收和重启恢复继续支持。没有可接收项不能显示全部完成。

界面默认中文标题、结构说明和状态，仅必要编号/符号/专有名词英文；真实原文不因显示翻译而改写。保留单人 20–30 项、单项接收少于 5 秒目标，不扩压测规模。PDF 与 Git 不阻塞接收；合并手动/自动编译信号，正式 PDF 独立于候选定位，候选预览冲突明确失败，成功替换才报成功，旧任务不能覆盖新 PDF/状态。

### 5. 显式迁移与恢复

提供 schema 1/2 → 3 迁移预览和显式应用，以共享锁和准确期望版本保护。完整保留 session、ID/计数器、不可变候选版本、决定、题目关联、批注/依赖、accepted 投影和后台备份检查点。迁移预览列出每个拟加标记的文件/准确边界与题号关联，只有现有位置可唯一确认时才建立固定 ID；失效项保留冲突，不能借迁移伪造恢复。保护现场正文与既有版本，新增纯标记不能作为重写原候选的理由。

旧项目继续可读并保留旧入口，不自动替换/删除状态；新项目使用 schema 3。迁移后一个活跃写入源，旧命令路由新状态，不实时双写。处理中断和作者并发改稿，不覆盖新文本。若需保留只读迁移标记防止旧扩展写入，须在预览说明；新格式发现不能依赖它。真实论文的迁移需另行审阅操作。
