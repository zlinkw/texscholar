## 必须修复的五项缺口

1. **F1 已确认备份事实保全。** 接收并远端确认后，作者继续改写再备份，不能用当前正文重算结果覆盖原来精确 ID/version 的已备份事实。复用既有账本，区分同 session 的历史发布凭据与当前保存状态；保留真实 commit/blob 关系及现有远端/祖先核验。不要写回审核 state 扰动前台版本，不以任意 done/hash 放行。
2. **F2 原文方案的无变化备份。** A 保留原文而 B/C 有修改是合法输入。接收 A 后，后台可依据精确源码/blob 和已经核实的远端提交记备份凭据，无需空提交或无意义改字。未远端确认仍阻止新批次；普通无变化检查不制造新 job/commit，更不能删除新批次保护门。
3. **F3 关联终结项跳转。** 修 inline_review 的未定义 requireMatch；已完结且有版本的关联项应核 source_match 后定位，冲突明确提示，精简项继续指向 Git。保留待审项工作台入口及精确问题关联。
4. **F4 关闭期间的同步回调。** dispose 清理对应面板的待同步集合；保存完成回调核对面板、请求和活动身份，关闭或重开后不得操作新页面。正式源事务仍正常完成，错误保留原因，不用宽泛 catch 掩盖。
5. **F5 返修默认说明一致。** README、生成的交接附件与 MCP/指南的外置状态和旧格式契约一致。schema3 默认保留，明确 discard/resolve 才改变相应批注；旧格式保持原支持行为。只统一说明，不为迁就旧文案改变数据默认值。

F1/F2 必须覆盖报告两个精确反例、未推送/离线、不同 session/version、旧凭据不能放行新接收、无关提交/分叉及范围外暂存。F3/F4 覆盖正常/失配/精简、保存前后关闭及关闭后重开另一项/另一项目；不重复把已解决的旧问题当新发现。

## 四项新功能的最终行为

### N1 本轮先放一边

卡片提供中文“先放一边”，仅保存作者的浏览队列选择并推进下一活跃项；目录有“暂缓”分组和恢复入口，重开保留。底层 deferred 不能充当作者暂缓状态；pending/rework、候选版本、批注、counter、问题闭合均不因暂缓改变。

默认自动跳转跳过暂缓项，保持现有筛选和显式导航优先；暂缓组可显式打开、恢复或选择处理，批量必须绑定用户明确选择的身份/版本/方案。活跃队列为空时显示剩余暂缓/冲突数量，不能称全部审核完毕。草稿沿用保存/明确放弃/取消契约，不静默丢弃。不要新增日历提醒或 AI 调用。

### N2 跨关闭和重启的草稿暂存

提供一次“暂存并关闭”，本机保存该项候选编辑、原文草稿及未提交批注，重开可恢复或明确放弃。暂存不写正式正文、不造候选新版、不转成已保存批注，不启动 AI/Git/PDF。普通“保存并切换”仍按原义保存候选/批注。

按 session、repo/owner、ID、version、原文基准及批注选区核对；新基准已变时保留旧草稿并明确提示核对，不偷偷套用到新版或新批次。错误可见；关闭中已有源事务仍完成，旧回调不覆盖新页草稿。优先复用现草稿结构及本地审核存储，不建立第二份审核决定权威或通用草稿框架。暂存内容不得进入论文 Git/导出/正式源；恢复/放弃可更新自有记录，不新增未经授权的完整文件清理机制。

### N3 历史候选对照

当前版本旁提供“历史”，选择仍存在的历史版本和方案，只读比较正文差异及当时批注。复用不可变对象、现有 inspect/version 和差异显示；默认仍展示当前候选，不额外复制历史正文。

采用旧文案时放入当前项的新候选草稿，经现有校验后由用户保存/接收，不能直接接受旧 version、跳过当前源核验或将旧选区定位到最新正文。已精简或新批次后不可用的对象明确说明，不承诺永久保留、不改变已有精简/新批次契约。

### N4 按审稿问题聚合核对

提供“按问题看”入口，以已确认的问题身份聚合正文/回复信关联数量、待审、冲突和待复核要求；点击进入现有精确条目。复用问题池、关联和 freshness，不让 AI 猜关联，未关联不等于没有修改，历史已精简也不能冒称遗漏。

作者可独立标记“本轮已核对”，与候选接收、拒绝和科学问题解决分别表示；相关版本/关联/批注有新变化时结合既有 freshness 显示需要再核对，不能伪装仍是已核对旧内容。新表必须提供全轮正文/回复分栏视图，不能仅给已有 QuickPick 换名字。不自动 AI/编译，不进入接收等待路径。

所有新增标题和按钮默认中文，仅符号、ID、必要专名保留英文。保留原入口；不新增常规弹窗、配置选择、额外同步或备份步骤。作者明确放弃数据及已有草稿冲突确认保留其必要语义。
