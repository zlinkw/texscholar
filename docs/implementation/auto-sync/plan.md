## 行为契约

1. 固定块/schema3 模式，正常 Ctrl+S、自动保存或外部保存后，后台自动协调受影响审核项，无额外同步按钮/弹窗步骤，不调用 AI、不接收候选、不改正式正文。插件启动/重新打开时读取实际已保存状态，补处理关闭期间变化，不自动迁移旧格式或开新批次。旧入口及旧格式现有能力保留。
2. 文档尚未保存时仅更新当前显示、保护草稿并暂禁受影响旧接收；不为逐字符输入不断持久生成版本，不擅自保存用户缓冲。保存后自动完成安全同步；磁盘与缓冲不一致时明确等待保存/核对，不能把磁盘称为全部最新编辑。
3. 无变化直接跳过：复用已有源版本/块快照和队列，重复文件通知不生成新候选版本、状态写入、提示或后台循环。只处理相关文件/变化块，其他段落/题目的修改不阻断无关候选。
4. 非重叠变化自动协调：保留作者文字、同一候选 ID、全部 A/B/C、旧不可变版本、计数器、问题/依赖和批注历史。必要时生成新版候选，原文批注实际引用变化才标需核对，不能自动解决/关闭延期批注或替作者决定。
5. 重叠、标记缺失/重复/损坏、无法唯一映射等保留双方内容并显式呈现，仅暂停受影响项；同一次保存内安全项继续完成同步。异常不能静默吞为成功，内部错误保留原因为可见失败，不把所有异常都降为普通冲突。修复后下次保存可自动重新尝试。
6. 合并 Ctrl+S/AutoSave/watcher 的同一变化，单个既有后台队列处理并在有新实际事件时排空最新工作；处理期间再次保存，旧结果不能覆盖新状态/源或新增批注。协调写入只改 sidecar/必要不可变对象，使用现有共享锁和状态/源版本 CAS；检查全部相关源后原子保存。每项计算失败不能污染随后安全项。无无限重试、定时轮询或新时间门槛。
7. 与接收/返修/批注保存共用现有互斥和最新版本核验。插件自己的接收/受控原文修改已有准确回执，刷新不能误判为另一轮手改、重复建版本；自动同步完成前旧 ID/version 请求必须停止，不能回退到其他项。多选仍全部预检。PDF、Git 后台队列不阻塞接收或同步。
8. 工作台同步时保留所有未保存候选/原文/批注草稿；同 ID 新版本不应要求作者放弃草稿才能继续，明确显示其旧基准与最新原文，并提供现有人工更新路径。普通保存不隐式改基准，自动流程不能改写作者草稿。安全无草稿时自动显示新版本并可继续审核。
9. 正常流程无同步确认。原手动同步入口保留为异常重试，文案/显示使其不再像必经操作；重叠时卡片直接给出原因及人工调整入口，不要求先点击同步。成功状态轻量显示“已自动同步”，不重复通知、不抢焦点。所有受影响指南同步说明真实行为。
